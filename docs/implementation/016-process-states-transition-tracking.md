# Task 10.1: Process States Transition Tracking

## Status
Completed

## Objective
Implement process lifecycle state transition tracking (`NEW` -> `READY` -> `RUNNING` -> `COMPLETED`) across all scheduling algorithms, providing a comprehensive log of state changes for debugging and visualization.

## What Was Implemented

1.  **`StateTransition` Struct**:
    *   Defined in `src/utils/StateTracker.h`.
    *   Records `pid`, `fromState`, `toState`, and `timestamp` for a single state transition event.

2.  **`StateTracker` Utility**:
    *   Implemented in `src/utils/StateTracker.h` and `src/utils/StateTracker.cpp`.
    *   Maintains a fixed-size array (`transitions[MAX_TRANSITIONS]`) to log state transitions sequentially without STL containers.
    *   Validates state transitions (e.g., `NEW -> RUNNING` is invalid; must go through `READY`).
    *   Provides `transitionProcess(Process& proc, ProcessState newState, int timestamp)` as a safe convenience method to update a process's state and log the event simultaneously.
    *   Includes `printTransitionLog()` to render a formatted ASCII table of all recorded transitions.

3.  **Integration into Schedulers**:
    *   `SchedulerBase` (`src/schedulers/SchedulerBase.h`):
        *   Added a `stateTracker` member variable.
        *   Exposed accessors `getStateTracker()` and `getStateTrackerMutable()`.
        *   Cleared the tracker in `reset()`.
    *   `FCFS`, `RoundRobin`, `PriorityScheduler`:
        *   Replaced direct assignments to `proc->state` with calls to `stateTracker.transitionProcess()`.
        *   Accurately captures `NEW -> READY` (arrival), `READY -> RUNNING` (dispatch), `RUNNING -> COMPLETED` (termination), and importantly in `RoundRobin`, `RUNNING -> READY` (preemption on quantum expiry).

4.  **Testing**:
    *   Created `tests/test_state_tracker.cpp` with 7 comprehensive test cases:
        *   Valid/invalid transition validation logic.
        *   Transition recording and state updating mechanics.
        *   Verification of the exact number of transitions generated by FCFS (9 events for 3 processes).
        *   Verification of preemption transitions in Round Robin.
        *   Protection against invalid state jumps.
    *   Integrated test suite into the Makefile.

5.  **Main Application Update**:
    *   Updated `src/main.cpp` to call `fcfs.getStateTracker().printTransitionLog()` to demonstrate the output.

## How It Works
Instead of simply assigning `process.state = ProcessState::RUNNING`, schedulers now call `stateTracker.transitionProcess(process, ProcessState::RUNNING, currentTime)`. This utility first validates that moving from the process's current state to the requested new state is a legal operation according to the OS process lifecycle. If valid, it records a `StateTransition` entry in its internal array, including the exact simulation time (`timestamp`) when the event occurred, and then updates the `process.state`.

## DSA / CS Concepts Used
*   **State Machine Validation**: Explicitly defining and enforcing legal state transitions prevents logic errors where a process skips necessary phases (like entering the ready queue).
*   **Event Logging (Audit Trail)**: Maintaining a chronological log of events provides an audit trail that is invaluable for verifying scheduler correctness, especially in preemptive algorithms like Round Robin.
*   **Fixed-size Array Management**: Operating within memory constraints by using a bounded array (`MAX_TRANSITIONS`) and avoiding dynamic allocations during the critical simulation loop.
